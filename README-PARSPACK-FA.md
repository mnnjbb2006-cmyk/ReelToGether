# استقرار اقتصادی ReelTogether روی PaaS پارس‌پک

این نسخه برای اجرای یک سرویس واحد FastAPI طراحی شده و برای دیتابیس به سرویس PaaS جداگانه نیاز ندارد. SQLite روی Persistent Volume نگهداری می‌شود.

## تنظیمات سرویس

- نوع سرویس: Python / FastAPI (اگر در پنل گزینه FastAPI وجود دارد همان را انتخاب کنید)
- نسخه Python: 3.12
- مسیر ریشه پروژه: پوشه‌ای که `requirements.txt`، `Procfile` و `main.py` در آن قرار دارند
- Build command: `pip install -r requirements.txt`
- Start command: اگر پنل Procfile را خودکار می‌خواند، خالی بگذارید؛ در غیر این صورت:
  `uvicorn main:app --host 0.0.0.0 --port 8000 --proxy-headers`
- تعداد instance/replica: یک عدد
- Worker: یک عدد؛ از چند worker یا چند replica استفاده نکنید چون حضور کاربران و WebSocketها فعلاً در حافظه همان پردازه نگهداری می‌شود.

## Persistent Volume

در پنل یک Persistent Volume به همین سرویس متصل کنید و Mount Path آن را دقیقاً `/data` قرار دهید. سپس متغیر محیطی زیر را اضافه کنید:

`DATA_DIR=/data`

فایل دیتابیس در مسیر زیر ساخته می‌شود:

`/data/reeltogether.db`

**مهم:** اگر Mount Path در پنل شما قابل انتخاب نیست یا مسیر دیگری انتخاب می‌کنید، مقدار `DATA_DIR` را دقیقاً برابر همان Mount Path قرار دهید. تا پیش از تأیید اتصال Volume، سرویس را برای کاربران واقعی منتشر نکنید؛ در غیر این صورت فایل SQLite ممکن است در لایه موقت کانتینر ساخته شود و با جایگزینی کانتینر از بین برود.

## متغیرهای محیطی

- `DATA_DIR=/data`
- `COOKIE_SECURE=true` (وقتی دامنه با HTTPS ارائه می‌شود)
- `TURN_URLS`، `TURN_USERNAME` و `TURN_CREDENTIAL` اختیاری‌اند و فقط در صورت داشتن TURN server تنظیم شوند.

`DATABASE_URL` را تنظیم نکنید تا برنامه از SQLite داخل Volume استفاده کند.

## دامنه و HTTPS

دامنه را به سرویس متصل و HTTPS را فعال کنید. پس از فعال شدن HTTPS، `COOKIE_SECURE=true` باشد تا کوکی ورود فقط از طریق HTTPS ارسال شود.

## محدودیت‌های نسخه اقتصادی

- یک سرویس PaaS و یک پردازه؛ بدون PostgreSQL و Redis جداگانه.
- SQLite برای شروع و بار سبک مناسب است؛ برای ترافیک/نوشتن همزمان زیاد، PostgreSQL بهتر است.
- اتاق‌ها، پیام‌ها و حساب‌ها در SQLite ماندگارند؛ حضور آنلاین، اتصال‌های WebSocket و وضعیت لحظه‌ای شرکت‌کنندگان در حافظه‌اند.
- چون وضعیت زنده در حافظه است، یک replica و یک worker نگه دارید. ری‌استارت اتصال‌های زنده را قطع می‌کند، اما اطلاعات ذخیره‌شده باقی می‌ماند.
- برای صدای WebRTC ممکن است در بعضی شبکه‌ها TURN لازم شود؛ این موضوع مستقل از دیتابیس است.
